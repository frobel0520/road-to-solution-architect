# 後端技術選擇速查表

| 技術 | 用途（一句話） | 什麼時候選 | 代價／要注意 | Example Retail 的例子 |
|---|---|---|---|---|
| 伺服器與 Runtime | 提供硬體、作業系統與程式語言執行環境 | 任何需要自己託管後端程式時 | 要負責版本升級、安全修補與資源規格 | 執行會員點數服務的雲端主機 |
| 後端框架 | 把路由、參數驗證與錯誤處理等共通雜事包好 | 多數商業 Web API，希望開發快且結構一致 | 要配合框架慣例；過度依賴時商業邏輯難抽離 | 會員與訂單 API 使用同一套後端框架 |
| 單體架構 | 所有模組一起測試、打包、部署 | 小型團隊、需求還在摸索、功能彼此高度相依 | 單一功能爆量只能整包擴展；改動要一起部署 | 4 人 IT 團隊重整購物網站核心 |
| 微服務 | 拆成獨立部署的服務，透過網路 API 溝通 | 多個團隊並行開發，或局部模組擴展需求差異極大 | 網路延遲、跨服務除錯與維運複雜度大增 | 未來流量極大時把商品目錄拆出來 |
| Serverless | 由事件觸發、算完即釋放、按量計費 | 間歇性、突發型或單純的獨立工作 | 有冷啟動延遲；單次執行時間與記憶體有限 | 週年慶大量產生電子發票 PDF |
| 同步處理 | 做完所有步驟才回覆使用者 | 決定交易成敗、顧客下一秒就要看結果的動作 | 步驟越長等待越久，外部故障會直接拖垮請求 | 結帳當下檢查庫存並扣款 |
| 非同步處理 | 先收下請求並回覆，耗時工作丟到背景執行 | 寄信、通知外部系統、產生大型報表 | 多出背景佇列與 worker；要處理重試與防重複 | 結帳後在背景寄確認信與通知物流商 |
| 認證（AuthN） | 確認「你是誰」 | 所有需要識別會員或管理員身分的系統 | 自己管密碼要單向雜湊加鹽，不可存明文 | 顧客用帳號密碼或第三方帳號登入 |
| 授權（AuthZ） | 確認「你能做什麼」 | 每次讀取或修改受保護資料時 | 必須在後端檢查擁有者與角色，不能只靠前端隱藏 | 會員只能看自己的訂單，不能看別人的 |
| Session＋Cookie | 伺服器記住登入狀態，瀏覽器帶編號 | 一般網站、需要隨時強制登出或立刻收回權限 | 伺服器要保存 Session 狀態，多台主機要共用 | 後台管理員異常時立刻強制登出 |
| Token（如 JWT） | 蓋了簽章的通行證，伺服器驗簽章即可 | 手機 App、跨多個後端服務傳遞身分 | 到期前難單方面撤銷；不可放機敏資料 | 手機 App 呼叫會員與訂單 API |
