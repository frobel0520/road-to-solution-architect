# 前端技術選擇速查表

| 技術 | 用途（一句話） | 什麼時候選 | 代價／要注意 | Example Retail 的例子 |
|---|---|---|---|---|
| HTML | 描述頁面上有什麼 | 所有網頁；重要內容直接寫在裡面 | 只管內容與結構，不管外觀 | 商品名稱與價格寫在 HTML |
| CSS | 描述外觀與排版 | 只改外觀的效果，優先用它 | 瀏覽器要等它才畫第一個畫面 | 手機與電腦不同的排法 |
| JavaScript | 讓頁面能互動、和伺服器交換資料 | 要依操作改變內容時 | 要下載與執行，慢手機最明顯；規則不能只在前端檢查 | 加入購物車不換頁 |
| 靜態網站 | 事先產生 HTML，直接送出 | 內容人人相同、不常變動、要被搜尋到 | 更新要重新產生；做不到個人化與即時 | 120 家門市資訊頁 |
| SPA | 瀏覽器用 JavaScript 組畫面，換畫面不重新載入 | 登入後、操作多、停留久的工具型畫面 | 第一個畫面慢；搜尋與分享預覽不可靠 | 客服後台 |
| SSR | 每次請求由伺服器組出 HTML | 內容常變又需要搜尋與快速的第一個畫面 | 要伺服器運算，流量大時要快取 | 三萬個商品頁 |
| Cookie | 瀏覽器保管、自動隨請求送出的小資料 | 登入用的憑證（加 HttpOnly、Secure、SameSite） | 容量小；每個請求都帶著 | 放 Session ID |
| Session | 資料放伺服器，瀏覽器只拿編號 | 登入狀態、權限等要信任的資料 | 伺服器要保存；多台伺服器要共用 | 登入後的會員身分 |
| localStorage | 瀏覽器裡給 JavaScript 用的儲存空間 | 不敏感、只和這台裝置有關的設定 | JavaScript 都讀得到，不放憑證；換裝置就沒有 | 深色模式、最近看過的商品 |
| 同源政策 | 網頁預設讀不到其他來源的回應 | 瀏覽器內建，不用選 | 網站與 API 不同來源時要另外放行 | shop 與 api 兩個主機名稱 |
| CORS | 由被呼叫的伺服器放行指定來源 | 網站要呼叫不同來源的 API | 只在瀏覽器生效，不能取代登入與權限檢查 | 會員 API 只允許購物網站 |
| 圖片最佳化 | 縮小、轉檔、延遲載入 | 圖片多的頁面，幾乎都該先做 | 要有產生多種尺寸的流程 | 週年慶主視覺圖 |
| 瀏覽器快取 | 下載過的檔案不用再下載 | 很少變動的靜態檔案 | 檔名要帶版本，否則更新後還用到舊檔 | CSS、JavaScript、商品圖 |
| 預留空間 | 替晚到的內容先留位置 | 圖片、廣告、之後才載入的區塊 | 要事先知道尺寸 | 列表頁上方的促銷橫幅 |
