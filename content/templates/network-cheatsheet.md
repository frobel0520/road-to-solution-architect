# 網路基礎技術選擇速查表

| 技術 | 用途（一句話） | 什麼時候選 | 代價／要注意 | Example Retail 的例子 |
|---|---|---|---|---|
| IP 位址 | 指到網路上的哪台機器 | 任何連線都需要 | 位址可能會變，所以對外用網址，不直接用 IP | 總部伺服器 203.0.113.10 |
| Port | 指到機器上的哪個程式 | 同一台機器跑多個服務 | 對外只開必要的 port，其他用防火牆擋住 | 網站用 443，報表系統只開給內部 |
| TCP | 可靠傳送：不遺失、不亂序 | 資料一個都不能掉 | 要建立連線、遺失時要等重送，比較慢 | 收銀機把交易送回總部 |
| UDP | 快速傳送，不保證送達 | 晚到等於沒用的即時資料 | 遺失、重複、亂序要自己處理 | App 的門市直播畫面 |
| DNS | 把網址換成 IP 位址 | 對外服務都用網址 | TTL 內舊答案會繼續被用；網域要續約 | 搬家前先把 TTL 調短 |
| HTTP | 瀏覽器與伺服器的一問一答 | 網頁與 API | 本身不加密、不記得使用者 | 4xx 先查請求，5xx 先查伺服器 |
| HTTPS | HTTP 加上加密與伺服器身分驗證 | 所有對外網站，內部有個資的系統也要 | 要管理憑證；不保護伺服器上的資料 | 抽獎頁的手機號碼還要確認儲存方式 |
| CDN | 把人人相同的內容放到離使用者近的地方 | 靜態內容多、使用者分散、有流量尖峰 | 更新要等快取過期；個人化內容不能快取錯 | 週年慶的商品圖片 |
| 反向代理 | 伺服器的統一入口 | 服務多，想集中處理 HTTPS 與規則 | 多一個要維護的元件；它壞了後面都連不到 | /api/ 送 API，其他送網站 |
| 負載平衡 | 把請求分給多台伺服器 | 一台撐不住，或不能一台壞就停擺 | 要設健康檢查；後端要能多台同時運作 | 三台後端，壞一台自動移出 |
