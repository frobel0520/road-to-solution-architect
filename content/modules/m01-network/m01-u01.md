## 情境

Example Retail 有 120 家門市、一個購物網站、一個 App，還有總部的好幾台伺服器。每天有幾十萬次的連線在這些設備之間來回：收銀機把交易送回總部、App 查點數、網站讀商品資料。

這些設備怎麼在茫茫網路裡找到正確的對象，而且不會把 A 的資料送給 B？答案從三個最基本的東西開始：IP 位址、port、封包。

## 觀念

### IP 位址：機器的門牌

網路上每台設備都需要一個位址，別人才能把資料送過來。這個位址叫 **IP 位址（IP address）**。常見的格式是四組 0～255 的數字，例如 203.0.113.10，這種是 IPv4。因為 IPv4 的數量快用完了，現在也越來越常見更長的 IPv6 位址。

比喻：IP 位址像門牌，告訴郵差要送到哪一棟。這個比喻不準的地方是：門牌通常不會變，但很多設備的 IP 位址會變，例如手機換了網路，位址就換了。所以人們用網址（例如 shop.example.com）來記網站，再由 DNS 查出當下的 IP 位址，這會在第 3 單元介紹。

### Port：同一棟樓裡的哪一戶

一台伺服器上可能同時跑好幾個程式：網站、資料庫、管理後台。光有 IP 位址，只知道送到哪台機器，不知道要交給哪個程式。**Port（連接埠）** 就是用來區分這件事的編號，範圍是 0～65535。

有些 port 有約定俗成的用途，例如網頁一般用 80（HTTP）與 443（HTTPS）。瀏覽器打開 https 開頭的網址時，沒寫 port 就會自動連 443。

IP 位址加上 port，才能精準指到「哪台機器上的哪個程式」。

### 封包：把資料切成小包裹

要傳的資料（例如一張商品圖片）不會一次整個送出去，而是切成許多小塊，叫做 **封包（packet）**。每個封包都寫著來源與目的地的 IP 位址和 port，各自在網路上被轉送，到達後再組回原本的資料。

切成封包的好處是：網路可以讓很多人的資料輪流通過，不會被一個大檔案佔住；某一包遺失時，也只需要補送那一包。至於誰負責確認封包都到齊、順序正確，是第 2 單元 TCP 與 UDP 的主題。

### 防火牆：只開放需要的 port

**防火牆（firewall）** 會依位址與 port 決定哪些連線可以通過。伺服器通常只對外開放必要的 port，例如網站只開 443，其他服務只允許內部連線。很多「連得到機器但連不到服務」的問題，原因就在這裡。

封包上寫著「送到 203.0.113.10 的 443」。網路依 IP 位址把它送到那台伺服器，防火牆確認 443 是允許的，伺服器再依 port 把它交給網站程式。送往報表系統 port 的外部連線，會被防火牆擋下。

## 取捨

一台機器上放多個服務時，常見的做法：

| 做法 | 適合的情況 | 代價 |
|---|---|---|
| 同一個 IP，不同 port | 服務少、主要給內部使用 | 使用者或其他系統要記得 port 號；防火牆規則要逐一管理 |
| 每個服務各用一個 IP | 服務要對外，而且彼此要明確隔開 | 要管理更多位址；IPv4 位址有限，對外的位址可能要付費取得 |
| 同一個 IP 與 port，前面放反向代理依網址分流 | 對外的網站與 API 很多，想統一走 443 | 多一個元件要維護；它故障時後面的服務都連不到 |

## 重點回顧

- IP 位址指到「哪台機器」，port 指到「機器上的哪個程式」，兩者合起來才能精準連線。
- 資料會切成封包傳送，每個封包都帶著來源與目的地的位址和 port。
- 網頁慣用 80（HTTP）與 443（HTTPS）。
- 連得到 IP、連不到 port，多半是服務沒啟動或被防火牆擋住。
