## 情境

找到伺服器、連線也建立了，接下來瀏覽器要開口說話：「請給我首頁」「請幫我把這個商品加入購物車」。雙方說話的格式，就是 **HTTP**。

Example Retail 的購物網站網址以 https 開頭，瀏覽器的網址列有個鎖頭。行銷部常聽廠商說「有 HTTPS 就安全了」，但資安負責人總是補一句「只安全一半」。這個單元說明 HTTP 怎麼說話，以及 HTTPS 的那個鎖頭到底保護了什麼。

## 觀念

### HTTP：一問一答

**HTTP（HyperText Transfer Protocol，超文本傳輸協定）** 規定了瀏覽器和伺服器怎麼對話：瀏覽器送出 **請求（request）**，伺服器回一個 **回應（response）**。一問一答，結束。

一個請求主要有四個部分：

| 部分 | 說明 | 例子 |
|---|---|---|
| 方法（method） | 想做什麼 | GET 讀取、POST 新增、PUT 更新、DELETE 刪除 |
| 路徑（path） | 對哪個東西 | /products/123 |
| 標頭（headers） | 附加資訊 | 用哪種語言、帶著哪個登入憑證 |
| 本文（body） | 要送的資料 | 加入購物車的商品與數量 |

回應則有 **狀態碼（status code）**、標頭與本文。狀態碼用第一個數字分類：

| 狀態碼 | 意思 | 常見例子 |
|---|---|---|
| 2xx | 成功 | 200 成功、201 已建立 |
| 3xx | 要去別的地方拿 | 301 永久搬家、304 沒變過，用你手上的就好 |
| 4xx | 請求這一端有問題 | 400 格式錯誤、401 沒登入、403 沒權限、404 找不到 |
| 5xx | 伺服器這一端有問題 | 500 內部錯誤、503 暫時無法服務 |

看到錯誤時，先看是 4xx 還是 5xx，就知道該先查請求還是查伺服器。

### HTTP 不記得你

HTTP 本身是 **無狀態（stateless）** 的：每個請求都是獨立的，伺服器不會記得上一個請求是誰送的。網站之所以知道「你已經登入了」，是每個請求都帶著一個識別資料（例如 Cookie），這會在模組 2 介紹。

### HTTPS：加上加密與身分驗證

HTTP 的內容是明文，路上經過的每台設備都看得到、改得了。**HTTPS** 是在 HTTP 外面包一層 **TLS（Transport Layer Security，傳輸層安全）**，提供三件事：

- **加密**：路上的人看不到內容，包括路徑、標頭與本文。
- **完整性**：內容被竄改時，對方會發現。
- **身分驗證**：伺服器要出示 **憑證（certificate）**，證明它真的是 shop.example.com，而不是冒牌的。憑證由瀏覽器信任的機構簽發。

### HTTPS 沒保護什麼

- **你連到哪個網站**：網域名稱在連線過程中通常仍然看得到，例如網路管理者可以知道你連了 shop.example.com，只是不知道你看了哪一頁。
- **伺服器上的資料**：資料送到之後，怎麼存、誰看得到，HTTPS 管不到。
- **網站本身是否可信**：詐騙網站也可以有 HTTPS。鎖頭只代表「你連到的就是網址上寫的那個網站」，不代表那個網站是好人。

比喻：HTTPS 像封口的掛號信，郵差看不到內容，收件人也簽了名。但信封上的地址還是看得到，而對方收到信以後怎麼保管，就不是郵局的責任了。

## 取捨

網站要不要全面使用 HTTPS：

| 做法 | 適合的情況 | 代價 |
|---|---|---|
| 全站 HTTPS，HTTP 一律轉址過去 | 幾乎所有對外網站，現在的預設做法 | 要管理憑證與到期更新；憑證過期時整個網站會出現安全警告 |
| 只有登入、結帳等頁面用 HTTPS | 已經不建議；只出現在很舊的系統 | 其他頁面可被竄改或偷看；瀏覽器會把 HTTP 頁面標示為不安全 |
| 內部系統也用 HTTPS | 公司內網有個資或機敏資料 | 內部也要管理憑證；但「內網就安全」的假設常常不成立 |

## 重點回顧

- HTTP 是一問一答：請求有方法、路徑、標頭、本文；回應有狀態碼、標頭、本文。
- 4xx 先查請求這一端，5xx 先查伺服器。
- HTTP 不記得你，登入狀態要靠每個請求都帶識別資料。
- HTTPS 保護傳輸途中的內容並驗證伺服器身分，但不保護伺服器上的資料，也不代表網站可信。
