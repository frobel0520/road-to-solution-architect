## 情境

顧客記得的是 shop.example.com，不是 203.0.113.10。但上一個單元說過，網路是用 IP 位址找到機器的。中間一定有某個東西，負責把網址翻成位址。

Example Retail 最近要把購物網站搬到新的伺服器，IP 位址會換。工程師說「改一下 DNS 就好」，但有經驗的同事提醒：改了 DNS，不代表所有顧客馬上就會連到新的伺服器。為什麼？

## 觀念

### DNS：網路的電話簿

**DNS（Domain Name System，網域名稱系統）** 負責把網址（正式名稱是「網域名稱」）換成 IP 位址。它不是一台伺服器，而是全世界很多伺服器分工合作的系統。

查詢 shop.example.com 時，大致是這樣：

1. 瀏覽器先問一台「遞迴解析器（recursive resolver）」，通常是電信業者或公司網路提供的 DNS 伺服器。
2. 解析器如果不知道答案，會從最上層開始問：先問根伺服器「.com 歸誰管」，再問 .com 的伺服器「example.com 歸誰管」。
3. 最後問到 example.com 的「權威伺服器（authoritative server）」，它保存著這個網域真正的紀錄，回答 shop.example.com 的 IP 位址。
4. 解析器把答案告訴瀏覽器，同時記下來，下次有人問就直接回答。

比喻：DNS 像查號台。不準的地方是：查號台通常是一個總機，DNS 則是一層一層轉介，而且每一層都可能把答案記起來。

### 常見的紀錄類型

| 紀錄 | 用途 |
|---|---|
| A | 網址對應到 IPv4 位址 |
| AAAA | 網址對應到 IPv6 位址 |
| CNAME | 網址是另一個網址的別名，例如 www 指向主網址 |
| MX | 這個網域的電子郵件要送到哪裡 |

### TTL：答案可以記多久

每筆 DNS 紀錄都有 **TTL（Time To Live，存活時間）**，單位是秒，意思是「這個答案最多可以記多久」。解析器與裝置在 TTL 內會直接用記住的答案，不再重新查詢。

TTL 長，查詢次數少、速度快；但紀錄改了以後，舊答案會繼續被使用到 TTL 過期為止。這就是「改了 DNS 不會立刻生效」的原因。

### 網域也要續約

網域是向註冊商登記、按年續約的。忘了續約，網域會過期，DNS 查不到紀錄，網站和用這個網域的電子郵件都會失效，即使伺服器完全正常。

## 取捨

設定 TTL 的長短：

| TTL | 適合的情況 | 代價 |
|---|---|---|
| 短（幾分鐘） | 近期要搬家、要切換伺服器，或需要快速切到備援 | 查詢次數多，第一次連線稍慢；權威伺服器的負擔增加 |
| 中（一小時左右） | 一般網站的平常狀態 | 臨時要換位址時，最多要等一小時才全部生效 |
| 長（一天以上） | 位址幾乎不會變的紀錄 | 一旦要改，舊位址會被記住很久；要提前好幾天規劃 |

## 重點回顧

- DNS 把網址換成 IP 位址，由遞迴解析器一層層問到權威伺服器。
- A 紀錄對應 IPv4，CNAME 是別名，MX 指定郵件伺服器。
- TTL 決定答案能被記多久；改 DNS 前要先把 TTL 調短。
- 「找不到這個網站」多半是 DNS 或網域出問題，不是伺服器忙。
