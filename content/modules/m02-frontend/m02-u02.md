## 情境

Example Retail 正在重新整理網站，工程師在會議上爭論：「門市資訊做成靜態的就好」「會員中心要做成 SPA」「商品頁一定要 SSR」。行銷主管聽不懂這三個詞，只知道每個人講的網站最後看起來都差不多。

差別不在畫面長什麼樣子，而在一個問題：**顧客看到的那份 HTML，是在哪裡、什麼時候產生的？** 答案不同，速度、成本、能不能被搜尋到，都會跟著不同。

## 觀念

### 靜態網站：事先做好，直接給

**靜態網站（static site）** 的每一頁，在顧客來之前就已經是做好的 HTML 檔案。顧客請求時，伺服器不用運算，把檔案原封不動送出去。

現在通常不是手寫每一頁，而是用工具從資料（例如 120 家門市的清單）一次產生全部頁面，這叫做 **SSG（Static Site Generation，靜態網站產生）**。內容要更新時，就重新產生一次。

因為每個人拿到的都一樣，靜態網站可以整個放在 CDN（模組 1 第 5 單元），又快又便宜，也沒有後端程式可以被攻擊。它的限制也在這裡：**內容因人而異，或變動很頻繁的頁面，沒辦法事先做好。**

### SPA：先給空殼，再由瀏覽器組畫面

**SPA（Single-Page Application，單頁應用程式）** 只有一份幾乎是空的 HTML，加上一大包 JavaScript。瀏覽器執行 JavaScript 之後，由它向伺服器要資料（通常透過 API，模組 3），再把畫面組出來。這種「在瀏覽器組畫面」的方式叫做 **CSR（Client-Side Rendering，用戶端渲染）**。

之後顧客在網站裡點來點去，都不會重新載入整頁，只是 JavaScript 換掉畫面的一部分、再要一點資料。操作起來很流暢，像手機 App。

代價有兩個：

- **第一個畫面慢。** 要等 JavaScript 下載並執行完，再等資料回來，顧客才看得到內容。手機越慢、訊號越差，感受越明顯。
- **搜尋引擎與分享預覽可能讀不到內容。** 它們拿到的是那份空殼 HTML。有些搜尋引擎會執行 JavaScript，但不保證完整、也比較慢；貼到通訊軟體時的預覽通常不會執行。

### SSR：每次請求，由伺服器組好再給

**SSR（Server-Side Rendering，伺服器端渲染）** 是伺服器收到請求時，當場查資料、組出完整的 HTML，再送給瀏覽器。瀏覽器一收到就能顯示，搜尋引擎也讀得到。

這其實是網站最早的做法。現在說的 SSR，通常還多一步：HTML 顯示之後，JavaScript 接著載入，把頁面「接手」過來，之後的操作就像 SPA 一樣不用整頁重載。

代價是每個請求都要伺服器運算，流量大時成本與壓力都比靜態網站高，通常要搭配快取。

### 不是三選一

同一個網站可以混用：門市資訊用靜態、商品頁用 SSR、會員中心用 SPA。很多開發框架也支援「以頁為單位」選擇做法，或是在靜態頁面裡只讓需要互動的那一小塊載入 JavaScript。選擇時是一頁一頁、一區一區地判斷，而不是整個網站只能選一種。

三列各是一種做法，由左到右是時間。框起來強調的是「HTML 內容產生的時間點」：靜態網站最早（發布時），SSR 在請求當下，SPA 最晚（在顧客的瀏覽器裡）。產生得越早，顧客越快看到畫面，但內容也越難做到即時與個人化。

## 取捨

| 做法 | 適合的情況 | 代價 |
|---|---|---|
| 靜態網站 | 內容人人相同、不常變動；要被搜尋到；想要最快、最便宜、最少維護 | 更新要重新產生；個人化與即時資料做不到，或要另外用 JavaScript 補上 |
| SPA | 登入後使用、操作多、停留久的畫面，例如後台、會員中心 | 第一個畫面慢；搜尋與分享預覽不可靠；JavaScript 出錯就整頁空白 |
| SSR | 內容常變動或因人而異，又需要搜尋與快速的第一個畫面，例如商品頁 | 要有伺服器即時運算；流量大時成本高，要設計快取 |

判斷時可以問三個問題：內容多久變一次？每個人看到的一樣嗎？需要被搜尋引擎找到嗎？

## 決策題

## 交給 AI 時要注意

- 先列出網站有哪幾類頁面，逐類說明更新頻率、是否因人而異、是否需要搜尋，再請它建議每一類的做法，不要只說「做一個網站」。
- 要求它說明每一類頁面的 HTML 是在什麼時候產生的，以及內容更新後多久會反映在網站上。
- 需要搜尋的頁面，完成後檢查伺服器送出的原始 HTML（不執行 JavaScript）裡有沒有標題、價格等主要內容。
- 問清楚選的做法需不需要一直開著的伺服器，以及流量變 10 倍時的成本。

## 重點回顧

- 三種做法的差別在 HTML 產生的地點與時間：發布時、請求時，或在瀏覽器裡。
- 靜態網站最快、最便宜，適合人人相同且不常變動的內容。
- SPA 操作流暢，但第一個畫面慢、搜尋不可靠，適合登入後的工具型畫面。
- SSR 兼顧即時內容與搜尋，代價是伺服器運算。
- 同一個網站可以依頁面混用不同做法。
