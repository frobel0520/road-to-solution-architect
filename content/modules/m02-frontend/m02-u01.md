## 情境

模組 1 講到：顧客在手機上輸入 shop.example.com，請求一路送到 Example Retail 的伺服器，伺服器回了一份回應。但這份回應並不是一張「畫好的圖」，而是幾份文字檔。把這些文字檔變成看得到、按得動的畫面，是瀏覽器的工作。

Example Retail 的小編常問工程師：「為什麼改個按鈕顏色要改一個檔，改按鈕的字要改另一個檔，按下去的反應又是第三個檔？」因為網頁本來就拆成三種語言，各管一件事。

## 觀念

### 三種語言，三種分工

**HTML（HyperText Markup Language，超文字標記語言）** 描述「頁面上有什麼」：這是標題、這是一段文字、這是圖片、這是按鈕。它只管內容與結構，不管長相。

**CSS（Cascading Style Sheets，階層式樣式表）** 描述「長什麼樣子」：顏色、字體大小、間距、哪個東西排在左邊或右邊、手機和電腦各怎麼排。

**JavaScript** 描述「會做什麼」：按下按鈕後把商品加入購物車、輸入手機號碼時檢查格式、不換頁就載入更多商品。它是三者之中唯一的程式語言。

比喻：蓋房子時，HTML 是樑柱與隔間，CSS 是油漆與裝潢，JavaScript 是電燈開關與電梯。比喻不準的地方是：房子蓋好就固定了，網頁的 JavaScript 卻可以在顧客使用時隨時增加隔間、重新粉刷。

### 瀏覽器顯示畫面的步驟

瀏覽器收到 HTML 之後，大致會做這幾件事：

1. **讀 HTML，建立文件結構。** 瀏覽器由上往下讀，把內容整理成一棵樹狀結構，叫做 **DOM（Document Object Model，文件物件模型）**。樹上的每個節點就是一個標題、一段文字或一個按鈕。
2. **讀到其他檔案就去下載。** HTML 裡會寫「這頁需要哪些 CSS、JavaScript 和圖片」，瀏覽器看到就各自發出請求。
3. **算出每個節點的樣式。** 把 CSS 的規則套到 DOM 上，決定每個節點的顏色、大小與字體。
4. **排版（layout）。** 依螢幕寬度算出每個節點的位置與尺寸。同一份 HTML 在手機和電腦上排法不同，就是這一步的結果。
5. **繪製（paint）。** 把算好的結果畫到螢幕上。

### JavaScript 可以隨時改畫面

JavaScript 能讀取和修改 DOM：新增一個節點、改一段文字、換一個樣式。DOM 一改，瀏覽器就會重新做第 3 到第 5 步受影響的部分，畫面跟著更新。「不換頁就把商品加進購物車、右上角的數字加一」就是這樣做到的。

這也帶來兩個要記住的後果：

- **瀏覽器要等 CSS 才畫。** 沒拿到 CSS 就先畫，顧客會先看到沒有排版的畫面再跳成正常樣子，所以瀏覽器通常會等 CSS 下載完才開始畫。CSS 檔越大，第一個畫面越晚出現。
- **JavaScript 可能讓瀏覽器停下來。** 瀏覽器讀 HTML 讀到一半遇到 JavaScript，預設會停下來，先下載並執行完再繼續，因為這段程式可能會改掉後面的內容。JavaScript 越多、越慢，畫面就越晚出現（模組 2 第 5 單元會再談）。

### 這些事都發生在顧客的裝置上

HTML、CSS、JavaScript 都是在顧客的瀏覽器裡執行的，所以叫做「前端（front end）」；在 Example Retail 伺服器上執行的程式則是「後端（back end）」。前端的程式碼顧客全都拿得到、也改得了，所以**不能把祕密放在前端，也不能只靠前端檢查**。例如「折扣不可超過五折」只寫在 JavaScript 裡，懂的人改一下就能送出一折的訂單，後端一定要再檢查一次。

## 取捨

同一個效果常常可以用不同的方式做到，原則是「能用越簡單的那一層，就不要用更複雜的」：

| 做法 | 適合的情況 | 代價 |
|---|---|---|
| 只用 HTML 內建的元件（連結、表單、按鈕） | 內容頁、一般表單；需要鍵盤操作、螢幕報讀都能正常使用 | 外觀與行為受限，特殊的互動做不出來 |
| HTML 加 CSS（滑過變色、展開收合、手機與電腦不同排法） | 只改外觀、不涉及資料的效果 | 複雜的條件判斷寫不出來 |
| 加上 JavaScript | 要和伺服器交換資料、依顧客的操作改變內容 | 要多下載和執行程式；出錯時功能就失效；在慢手機上最明顯 |

## 決策題

## 交給 AI 時要注意

- 說清楚哪些內容必須在 HTML 裡就看得到（例如商品名稱與價格），哪些可以等 JavaScript 載入後再出現。
- 要求用 HTML 內建的按鈕、連結與表單元件，不要用一般的區塊加上 JavaScript 模擬；完成後用鍵盤操作一遍確認。
- 價格、折扣、庫存這類規則，要求後端一定要檢查，前端的檢查只是讓顧客早一點看到提示。
- 完成後請它把 JavaScript 關掉再開一次頁面，回報哪些內容還看得到、哪些功能失效。

## 重點回顧

- HTML 管內容與結構，CSS 管外觀，JavaScript 管互動。
- 瀏覽器把 HTML 讀成 DOM，套上 CSS，排版後繪製成畫面。
- JavaScript 可以隨時修改 DOM，畫面會跟著更新。
- CSS 和 JavaScript 都可能讓第一個畫面變晚出現。
- 前端的程式在顧客的裝置上執行，祕密與規則檢查不能只放在前端。
