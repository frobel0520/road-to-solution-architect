## 情境

模組 1 第 4 單元提過：HTTP 不記得你。每個請求對伺服器來說都是全新的，它不知道這個請求和三秒前那個請求是不是同一個人送的。

但 Example Retail 的顧客登入一次之後，逛十幾頁都還是登入狀態；購物車裡的東西隔天還在；上次選的深色模式也還記得。這些「記得」不是 HTTP 做的，而是有人把資料存了起來。存在哪裡、誰讀得到，決定了它安不安全、適合放什麼。

## 觀念

### Cookie：瀏覽器幫你保管、自動附上的小紙條

**Cookie** 是伺服器請瀏覽器保存的一小段文字。伺服器在回應裡說「請記住這個」，瀏覽器就存起來；之後每次對同一個網站發出請求，瀏覽器都會**自動**把它附上。

「自動附上」是 Cookie 最重要的特性，登入狀態就是靠它維持的。Cookie 還可以設定幾個屬性：

| 屬性 | 作用 |
|---|---|
| 到期時間 | 沒設定的話，關掉瀏覽器就消失；有設定就保留到那個時間 |
| HttpOnly | 頁面上的 JavaScript 讀不到，只有瀏覽器在發請求時會附上 |
| Secure | 只在 HTTPS 連線時才傳送 |
| SameSite | 限制「從別的網站發起的請求」能不能帶上這個 Cookie |

Cookie 的容量很小，而且每個請求都會帶著，所以不適合放大量資料。

### Session：資料放在伺服器，瀏覽器只拿號碼牌

把「會員編號 12345、已登入」直接寫在 Cookie 裡很危險，因為顧客可以自己改成 12346。常見的做法是 **Session（工作階段）**：

1. 顧客登入成功，伺服器在自己這邊建立一筆紀錄，寫著是誰、什麼時候登入。
2. 伺服器產生一個很長、猜不到的亂數當編號（Session ID），用 Cookie 交給瀏覽器。
3. 之後每個請求，瀏覽器自動附上這個編號，伺服器拿它查出對應的紀錄，就知道是誰。

比喻：像寄物櫃。東西（資料）放在櫃子裡（伺服器），你手上只有號碼牌（Session ID）。比喻不準的地方是：號碼牌被別人撿走，他就能開你的櫃子，所以這個 Cookie 一定要用 HttpOnly 和 Secure 保護，登出時伺服器也要把那筆紀錄作廢。

另一種做法是不在伺服器保存紀錄，而是把身分資料加上伺服器的簽章後交給瀏覽器保管，伺服器收到時驗證簽章有沒有被改過。這和登入方式有關，模組 4 第 4 單元再談。

### localStorage：存在瀏覽器裡，給 JavaScript 用

**localStorage** 是瀏覽器提供給網頁的儲存空間。和 Cookie 相比有三個差別：

- **不會自動送給伺服器。** 只有頁面上的 JavaScript 能讀寫。
- **容量大得多**，而且沒有到期時間，除非顧客清除瀏覽資料，否則一直都在。
- **同一個網站的 JavaScript 都讀得到。** 沒有像 HttpOnly 那樣的保護。

所以它適合放不敏感、只和這台裝置有關的資料：深色模式、最近看過的商品、填到一半的表單。還有一個類似的 **sessionStorage**，差別是只在目前這個分頁有效，分頁關掉就清除。

### 共同的限制：都在顧客手上

存在瀏覽器裡的東西（Cookie 與 localStorage），顧客自己都看得到、也改得了，換一台裝置就沒有。因此：

- 不能把「信任」建立在瀏覽器存的內容上。價格、點數餘額、權限，一律以伺服器的資料為準。
- 需要跨裝置的資料（例如購物車在手機加、回家用電腦結帳），必須存在伺服器。

## 取捨

| 存放位置 | 適合存什麼 | 代價 |
|---|---|---|
| Cookie（加 HttpOnly、Secure） | 登入用的 Session ID 這類要自動送給伺服器的小憑證 | 容量小；每個請求都帶著；屬性沒設好會被偷或被別的網站利用 |
| 伺服器的 Session | 登入狀態、權限等伺服器要信任的資料 | 伺服器要保存與清理；多台伺服器時要放在大家都讀得到的地方（模組 6） |
| localStorage | 不敏感、只和這台裝置有關的設定與暫存 | JavaScript 都讀得到，不能放憑證；換裝置或清除資料就不見 |
| 伺服器的資料庫 | 要長期保存、跨裝置的資料，例如購物車與訂單 | 每次讀寫都要經過網路與伺服器 |

## 決策題

## 交給 AI 時要注意

- 明確指定登入憑證的存放方式（例如 HttpOnly、Secure、SameSite 的 Cookie），不要讓它自己選；完成後檢查它有沒有把憑證寫進 localStorage。
- 要求說明每一筆存在瀏覽器的資料：存在哪裡、多久過期、被顧客改掉會怎樣。
- 要求登出時伺服器端的 Session 也要作廢，而不是只刪掉瀏覽器的 Cookie。
- 檢查有沒有把個資或權限判斷放在瀏覽器儲存空間裡。

## 重點回顧

- Cookie 存在瀏覽器，會自動隨請求送到伺服器，適合放登入用的小憑證。
- Session 把資料留在伺服器，瀏覽器只保存一個猜不到的編號。
- localStorage 只有頁面的 JavaScript 讀得到，適合不敏感的裝置設定，不適合放憑證。
- 存在瀏覽器的資料顧客都改得了；要信任的資料與跨裝置的資料放在伺服器。
