## 情境

Example Retail 的 IT 團隊新來了一位同事。他不是工程師出身，但每天開會都聽到 CDN、API、快取、佇列這些詞。主管給他一個目標：三個月內，至少要聽得懂大家在討論什麼，能問出好問題，並且知道一個技術選擇大概會有什麼代價。

他的時間很零碎，常常只能在通勤時用手機讀十分鐘。這門課就是為這種情況設計的。

## 觀念

### 每個單元都回答四件事

不管介紹的是哪一種技術，每個單元都會回答同樣的四個問題：

1. **它是什麼**：用一般人聽得懂的話說明，必要時用比喻，並說清楚比喻在哪裡不準。
2. **沒有它會怎樣**：先講問題，再講技術。知道它解決什麼問題，比背定義更容易記住。
3. **有哪些替代方案、怎麼選**：幾乎每個技術都有替代方案，沒有一個永遠最好，只有在某個情況下比較適合。
4. **一題情境決策題**：用 Example Retail 的情境，檢查你能不能做出判斷。

### 單元的段落

| 段落 | 讀的時候看什麼 |
|---|---|
| 情境 | Example Retail 遇到什麼問題；先想想如果是你會怎麼做 |
| 觀念 | 技術是什麼、怎麼運作；第一次出現的術語會中英並列 |
| 架構圖 | 這個技術放在系統的哪個位置 |
| 取捨 | 幾個選項的比較；重點在每個選項的「代價」那一欄 |
| 決策題 | 作答後會顯示每個選項的解析，包括錯的選項在什麼情況下會變成對的 |
| 重點回顧 | 3～5 點，複習時只看這裡也可以 |

### 遇到看不懂的詞

這門課假設你沒有寫過程式。術語第一次出現時會中英並列，例如「網域名稱系統（DNS）」，因為工作上和網路文章裡多半直接用英文，兩個都認得才查得到資料。縮寫第一次出現時也會展開說明。

如果某個詞在單元裡沒有解釋，通常是因為它屬於後面的模組。這時先記住「它是某個環節的工具」就好，不必停下來查到底。等讀到對應的模組，再回頭看會清楚很多。真的卡住時，回到模組 0 第 1 單元的全課地圖，找出這個詞在整條路的哪一段。

### 比喻的用法

單元裡常用生活中的比喻，例如把 IP 位址比喻成門牌、把快取比喻成放在手邊的常用物品。比喻能幫你快速抓到重點，但每個比喻都有不準的地方，單元會一併說明「這個比喻在哪裡不成立」。記住技術本身的行為，不要只記比喻。

### 進度怎麼存

每個單元最下面有「完成本單元」按鈕，決策題的作答也會自動記住。進度只存在你現在用的這個瀏覽器：換手機、換瀏覽器，或清除瀏覽器資料，進度就不會跟著走。

### 速查表

模組 1～6 讀完後，各有一頁「技術選擇速查表」，把模組裡每個技術的用途、什麼時候選、代價整理在一張表裡。你可以複製範本，用自己的話重寫一次，這是檢查自己有沒有讀懂最快的方法。

## 取捨

讀的方式可以依時間調整：

| 讀法 | 適合的情況 | 代價 |
|---|---|---|
| 完整讀一個單元 | 有 10 分鐘以上的完整時間 | 時間不夠時容易中斷，下次要重新進入狀況 |
| 只讀情境與重點回顧 | 只有 2～3 分鐘，想先知道這個單元在講什麼 | 只知道結論，不知道為什麼；決策題多半答不出來 |
| 先做決策題，再讀內容 | 已經有一些基礎，想先測自己 | 第一次接觸的主題，題目會看不懂，反而浪費時間 |

## 重點回顧

- 每個單元都回答四件事：是什麼、沒有它會怎樣、替代方案怎麼選、一題決策題。
- 讀「取捨」時，重點在每個選項的代價。
- 決策題要能說出每個選項為什麼對或錯，猜對不算理解。
- 進度只存在目前的瀏覽器，換裝置不會跟著走。
- 讀完一個模組，用速查表整理一次。
