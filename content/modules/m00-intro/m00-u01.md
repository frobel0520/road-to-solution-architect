## 情境

一位顧客在手機上輸入 Example Retail 的網址，一秒後看到首頁的商品與優惠。對顧客來說只是「打開網站」，但這一秒裡，手機、網路上的好幾台設備、Example Retail 的伺服器與資料庫，已經接力完成了一長串工作。

週年慶時，這一秒可能變成十秒，甚至打不開。IT 團隊要找出是哪一段出了問題，就得先知道整條路上有哪些站。這門課就是把這條路拆成一段一段，每段介紹一種技術。

## 觀念

### 一個請求的旅程

打開網站時，瀏覽器送出一個「請求（request）」，伺服器回一個「回應（response）」。這一來一回大致經過下面這幾站：

1. **查網址**：瀏覽器先把網址（例如 shop.example.com）換成電腦看得懂的 IP 位址。負責這件事的是 DNS。
2. **連上伺服器**：手機用這個位址，透過網路把資料切成一個個封包送出去。資料要可靠送達，靠的是 TCP 等傳輸方式；內容要加密，靠的是 HTTPS。
3. **先遇到前面的關卡**：請求不一定直接到 Example Retail 的伺服器。圖片、網頁檔案可能由離你最近的 CDN 直接回應；其他請求會先經過負載平衡，分給其中一台伺服器。
4. **後端處理**：伺服器上的程式（後端）收到請求，判斷你是誰、能看什麼，再去資料庫拿商品與優惠資料。
5. **回到瀏覽器**：伺服器把結果送回來，瀏覽器把 HTML、CSS、JavaScript 組成你看到的畫面。

App 的流程幾乎一樣，只是第 5 步改由 App 畫畫面，而且 App 通常透過 API 只拿資料，不拿整個網頁。

### 每一站對應的模組

| 旅程 | 主要技術 | 模組 |
|---|---|---|
| 查網址、傳封包、加密、分流 | DNS、TCP、HTTPS、CDN、負載平衡 | 模組 1 網路基礎 |
| 瀏覽器組畫面、存登入狀態 | HTML／CSS／JavaScript、Cookie | 模組 2 前端與瀏覽器 |
| 系統之間交換資料 | API、REST、Webhook | 模組 3 API 與系統溝通 |
| 伺服器上的程式 | 框架、微服務、認證與授權 | 模組 4 後端基礎 |
| 資料存在哪裡 | SQL、NoSQL、索引、交易 | 模組 5 資料庫 |
| 流量變大時怎麼撐 | 快取、佇列、複寫、分片 | 模組 6 擴展與效能 |

## 取捨

這門課的模組可以用不同順序讀：

| 讀法 | 適合的人 | 代價 |
|---|---|---|
| 依序讀模組 0～6 | 第一次接觸這些技術，想建立完整的全貌 | 花的時間最多；有些已經懂的地方也要讀過 |
| 先讀 Web（模組 1～3），再挑後端 | 平常接觸網站或 App，想先看懂自己每天在用的東西 | 讀模組 4～6 時，可能要回頭補模組 1 的觀念 |
| 遇到問題才查對應模組 | 已經有一些基礎，只想補某一塊 | 容易只懂片段，看不出技術之間的關係 |

## 決策題

## 重點回顧

- 打開網站是一個請求與回應的來回：查網址、連線、經過 CDN 與負載平衡、後端處理、查資料庫、瀏覽器組畫面。
- 每一段都有對應的技術，本課把它們分成 6 個模組。
- 只有某一段變慢時，比對「哪些功能正常、哪些不正常」，可以縮小問題範圍。
- 第一次讀建議依序讀；之後可以把這張全課地圖當索引。
