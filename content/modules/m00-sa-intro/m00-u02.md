## 情境

Example Retail 的 IT 團隊開始用 AI coding agent 開發。第一週的成果讓大家很興奮：一支會員點數查詢 API 半天就寫好，連測試都一起產生了。

但上線前的整合測試發現一連串問題：已過期的點數沒有扣除、同一個人在門市和電商各有一個帳號時點數算了兩次、查詢時間在大量資料下變得很慢。程式寫得很快，可是沒有人說清楚它應該做到什麼。IT 主管問你：「有了 agent 之後，SA 的工作到底要怎麼調整？」

## 觀念

### 瓶頸從「寫」移到「說清楚」與「驗證」

過去一個功能的時間，大部分花在實作。實作交給 coding agent 之後，寫程式的時間大幅縮短，剩下的工作反而變得顯眼：

- **規格**：agent 會照字面完成任務。沒寫出來的業務規則、例外情況與限制，它只能猜，而且猜錯時看起來仍然很合理。
- **驗證**：程式產生得越快，需要確認的東西越多。沒有清楚的驗收標準，就只能憑感覺判斷「好像可以」。
- **整合**：每個功能各自正確，不代表串起來正確。跨系統的資料一致、錯誤處理與效能，都要在整合時才看得到。

### 規格要寫到 agent 不用猜

給人看的需求可以留一些空間，因為工程師會來問。給 agent 的規格則要明確寫出：

| 項目 | 例子 |
|---|---|
| 介面 | 輸入哪些欄位、回傳什麼、錯誤怎麼表示 |
| 業務規則 | 點數到期日怎麼算、重複會員怎麼合併 |
| 限制 | 不能修改 POS 的資料表、回應時間上限 |
| 驗收案例 | 給定某個會員資料，應該得到什麼結果 |
| 不做的事 | 這次不處理點數轉贈 |

### 驗證要分清楚誰判斷

- **機器檢查**：測試、型別、靜態分析、效能量測。可以重複執行。
- **人工判定**：業務規則是否符合、使用者體驗是否合理。要有人簽核。
- **尚未驗證**：還沒檢查的就明寫「未驗證」，不因為建置成功就當作通過。

### 估時以審查與整合為主

實作變快之後，時程主要取決於需求釐清、審查、整合與驗收。外部系統的回應速度、廠商的配合、使用者測試的排程，都不會因為 agent 變快。估時時把這些工作列出來，才不會給決策者錯誤的期待。

### 實例：把點數查詢重新交代一次

回到情境裡的點數查詢 API。第一次交代只有一句話；第二次，SA 和行銷部、門市營運部確認後，把規格改寫成下面這樣再交給 agent：

| 項目 | 內容 |
|---|---|
| 目的 | 會員在 App 與門市查詢可用點數 |
| 業務規則 | 可用點數＝已入帳點數－已使用－已過期；點數自入帳日起 12 個月後的月底到期（行銷部確認的規則） |
| 重複會員 | 同一手機號碼視為同一人，查詢結果合併；合併規則由會員整合任務負責，這支 API 只讀取合併後的結果 |
| 限制 | 不直接讀 POS 資料庫；查詢回應時間的上限在品質屬性情境裡定義 |
| 驗收案例 | 剛好今天到期的點數不算可用；沒有任何點數的會員回傳 0，不是錯誤 |
| 不做的事 | 點數轉贈、點數兌換 |

這份規格多花了一天釐清，但 agent 第一次產生的結果就通過了大部分驗收案例，剩下的問題也很容易定位：不是規則沒寫，就是實作沒照規則做。

### 仍然由人決定的事

範圍與優先順序、架構與取捨、資安與個資的邊界、驗收是否通過，都必須由人負責。agent 可以提出選項，但不能替你承擔後果。

## 取捨

規格要寫多細？

| 做法 | 適合的情況 | 代價 |
|---|---|---|
| 一句話交代任務 | 一次性的原型、丟掉也沒關係的實驗 | 沒寫的規則全靠 agent 猜，結果難以驗收 |
| 完整規格＋驗收案例 | 會上線、有業務規則或跨系統整合的功能 | 前期要花時間釐清需求，需要懂業務的人參與 |
| 只寫介面，規則留給審查時補 | 規則還在變動，想先看到可操作的版本 | 審查負擔變重，容易漏掉沒想到的規則 |

會員平台的點數、會員合併都牽涉金額與個資，屬於第二種。

## 決策題

## 交給 AI 時要注意

- 每個任務都附上業務規則、限制與「不做的事」，不只寫要做的功能。
- 驗收案例在交付前寫好，包含正常、邊界與錯誤情況，例如「點數剛好在今天到期」。
- 要求 agent 回報它做了哪些假設，逐一確認，不讓假設默默變成規則。
- 驗收紀錄分開寫機器檢查、人工判定與尚未驗證，沒驗證的不寫成通過。
- 估時把規格、審查、整合、驗收分開列，不只估實作。

## 重點回顧

- 實作交給 coding agent 後，瓶頸移到規格、審查、整合與驗收。
- 規格要寫到 agent 不用猜：介面、業務規則、限制、驗收案例與不做的事。
- 驗證分成機器檢查、人工判定與尚未驗證，三者分開記錄。
- 範圍、取捨、資安邊界與驗收結果，仍然由人決定與負責。
