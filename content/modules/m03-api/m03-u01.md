## 情境

Example Retail 的會員資料只有一份，但需要它的地方很多：購物網站要顯示點數，手機 App 要顯示會員條碼，門市的收銀系統要查會員等級，物流商要拿到收件地址。

最直接的想法是「大家都連到同一個資料庫自己查」。這在只有一兩個程式時行得通，但系統一多就會出事：有人改了一個欄位，三個系統同時壞掉；外部廠商看得到不該看的資料；沒有人說得清楚誰在用什麼。系統之間需要一個講好的溝通方式。

## 觀念

### API：程式和程式之間的窗口

**API（Application Programming Interface，應用程式介面）** 是一個系統提供給其他程式使用的窗口。它規定了：

- **可以要求什麼**：例如「查詢會員」「建立訂單」「取消訂單」。
- **要提供什麼**：例如查詢會員要給會員編號。
- **會得到什麼**：例如會員姓名、等級、點數，各是什麼格式。
- **出錯時會怎樣**：例如會員不存在時回什麼。

使用的一方只要照規定提出要求，不需要知道對方內部是用什麼語言寫的、資料存在哪種資料庫、有幾台伺服器。

比喻：像餐廳的菜單與點餐櫃台。客人照菜單點餐，不用進廚房，也不用知道食材放哪裡；廚房換了爐子、換了廚師，只要菜單上的菜還是同樣的東西，客人就不受影響。比喻不準的地方是：客人看到菜單變了會自己調整，程式不會。菜名改一個字，程式就點不到菜。

### 為什麼說它是合約

提供 API 的一方和使用 API 的一方，等於簽了一份合約：「你照這個格式問，我就照這個格式答。」

這份合約帶來兩個好處：

- **內部可以自由改。** 會員系統想換資料庫、重寫程式，只要對外的輸入與輸出不變，其他系統完全不用動。
- **可以控制對方能做什麼。** 物流商只拿得到出貨需要的欄位，看不到會員的消費紀錄。

也帶來一個責任：**合約不能隨便改。** 一旦有人照著它寫了程式，任何改動都可能讓對方的程式壞掉。

### 哪些改動會破壞對方

| 改動 | 會不會破壞既有的使用者 |
|---|---|
| 在回應裡新增一個欄位 | 通常不會，舊程式會忽略不認識的欄位 |
| 新增一個功能 | 不會 |
| 新增一個選填的輸入 | 不會 |
| 移除或改名回應裡的欄位 | 會 |
| 改變欄位的格式或意義（例如金額從「元」改成「分」） | 會，而且最危險，因為程式不會出錯，只是算錯 |
| 新增一個必填的輸入 | 會 |

會破壞對方的改動叫做**破壞性變更（breaking change）**。處理的原則是「先加、後減」：先加上新的，讓新舊並存一段時間，通知使用者，確認沒人使用舊的之後才移除。怎麼管理版本，本模組第 5 單元再談。

### 使用者是誰，決定了改動有多難

- **內部 API**：只有自己團隊的系統在用。可以協調同時更新，改動最容易。
- **給自己 App 用的 API**：看起來是自己人，但顧客不一定會更新 App，舊版本可能在外面存活很久。
- **給合作夥伴或公開的 API**：對方的開發時程不受你控制，改動要提前很久公告。

### 文件也是合約的一部分

API 要寫成文件，列出每個功能的輸入、輸出與錯誤。現在常見的做法是用固定的格式寫成一份規格檔，可以自動產生說明網頁，也可以用來自動檢查程式的實際行為有沒有偏離規格。沒有文件的 API，使用的人只能用猜的，猜的結果就成了沒有人敢動的隱形合約。

## 取捨

讓另一個系統取得資料的幾種方式：

| 做法 | 適合的情況 | 代價 |
|---|---|---|
| 直接共用資料庫 | 同一個團隊、同一個系統裡的不同部分 | 對方依賴資料表結構，改不動；看得到所有欄位；難以追蹤誰做了什麼 |
| 提供 API | 不同團隊、不同公司，或有多種使用者 | 要設計、開發、寫文件與長期維護；改動要顧及使用者 |
| 定期交換檔案 | 資料量大但不需要即時，例如每日對帳；或對方沒有能力串接 API | 不即時；格式出錯要到處理時才發現；檔案的保存與傳送要另外保護 |

## 決策題

## 交給 AI 時要注意

- 先請它寫出 API 的規格（每個功能的輸入、輸出、錯誤），審過之後才開始實作。
- 修改既有 API 時，要求它列出這次改動是否會破壞既有使用者，並說明判斷依據。
- 說明這個 API 的使用者是誰（內部、自家 App、外部夥伴），以及舊版使用者會存在多久。
- 要求回應只包含使用者需要的欄位，不要把整筆資料庫紀錄原封不動送出去。

## 重點回顧

- API 是系統提供給其他程式的窗口，規定能問什麼、怎麼問、得到什麼。
- 它是一份合約：內部可以自由改，對外的輸入與輸出不能隨便改。
- 移除、改名、改變意義是破壞性變更；新增通常是安全的。
- 改動的原則是先加後減，新舊並存一段時間。
- 使用者越不受自己控制，改動的成本越高。
