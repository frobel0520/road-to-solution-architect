## 1. 摘要

SWE Trial 是軟體工程技術導覽的自學網站：介紹軟體工程裡常見的技術，每項技術講清楚是什麼、解決什麼問題、什麼時候用、和替代方案怎麼選。

先做兩個領域：Web 與網路基礎、資料與後端。只講概念與選擇，不寫程式；手機和電腦都能讀，進度自動儲存。

課綱、單元格式與貫穿案例見 [`curriculum.md`](curriculum.md)。

## 2. 目標學習者

- 技術基礎不深，想看懂軟體工程常見技術的人；不假設有開發經驗。
- 還沒決定往哪個方向發展，想先建立全貌。
- 學習時間零碎，常在手機上閱讀。

## 3. 目標與成功標準

| 目標 | 成功標準 |
|---|---|
| 看懂常見技術 | 7 個模組、30 個單元全部上線，每個單元都有決策題 |
| 能做技術選擇 | 模組 1～6 各有一頁技術選擇速查表（範本與 Example Retail 範例） |
| 隨時接續學習 | 手機與電腦都能使用；同一個瀏覽器重開後進度還在（第一階段）；跨裝置同步（第二階段） |
| 內容可信 | 每個單元由使用者審閱後才標為已審閱；提到特定產品或雲端服務時附官方來源與查證日期 |
| 零月費 | 營運期間沒有任何持續費用 |
| 效能 | 通過 `docs/03-system-design.md` 第 6 節的門檻 |

## 4. 範圍

### 4.1 第一階段（公開級）

- 頁面：首頁（學習路線與進度總覽）、模組頁、單元頁、案例介紹頁、速查表頁。
- 內容：30 個單元，依 `curriculum.md` 的單元格式。
- 決策題：作答後立即顯示每個選項的解析。
- 進度：單元完成狀態、決策題作答、上次閱讀位置，存在瀏覽器（localStorage）。
- 速查表：可以一鍵複製的 Markdown 範本與範例。
- 版面：手機與電腦都能使用，跟隨系統的淺色／深色模式。
- 部署：Cloudflare Worker static assets，由 GitHub Actions 從 `main` 部署。

### 4.2 第二階段（產品級）

- Google 登入，進度存在 D1，跨裝置同步。
- 第一次登入時，把瀏覽器裡的進度合併上傳。
- 開工前補齊產品級文件：`docs/02-system-analysis.md`、`docs/04-release-gate.md`，`docs/03-system-design.md` 補完整設計；`AGENTS.md` 的專案級別改為產品級。
- 開放對象（只有擁有者，或任何 Google 帳號）待決定。

### 4.3 明確排除

- 程式教學、線上程式執行環境。
- 證照考試對應。
- 影片。
- 留言、社群、排行榜。
- 收集學習者的筆記或速查表（學習者在自己的筆記裡整理）。
- AI 助教或聊天功能：會產生按量計費的 API 費用，違反零月費。
- 使用分析與追蹤腳本。
- 引用 Learning Atlas 的其他課程（CR-001 決定兩者各自獨立）。
- 雲端／DevOps、資安、AI 應用領域：之後再決定要不要加，加入時另提 CR。

## 6. 限制與假設

- 零月費：只使用 Cloudflare 免費方案與 GitHub 免費功能。
- 內容由 AI 協助撰寫、使用者審閱。內容正確性與結構驗證分開進行、分開記錄。
- 課程案例全部是虛構的。
- 單人維運。

## 7. 風險

| 風險 | 影響 | 對策 |
|---|---|---|
| 內容量大，零碎時間難以審完 | 上線延遲 | 分批上線；每批先通過結構驗證，未審閱的單元在網站上標示「內容待審閱」 |
| AI 撰寫的內容有事實錯誤 | 學到錯誤觀念 | 規格與產品事實附官方來源與查證日期；使用者審閱後才標為已審閱 |
| 寫給初學者時太淺或太深 | 讀不下去或沒收穫 | 先做模組 0、1 樣板，使用者確認難度後才寫其他模組 |
| 產品或服務變動 | 內容過時 | 只在必要時提產品名稱；有提到的單元記錄查證日期，定期複查 |
| 清除瀏覽器資料或使用無痕模式 | 第一階段的進度遺失 | 網站明確說明進度只存在這個瀏覽器；第二階段提供同步 |
| 第二階段改為產品級的流程成本 | 時程拉長 | 第一階段的進度格式先為同步設計好（`docs/03` ADR-003） |
